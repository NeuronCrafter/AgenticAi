Fundamentals

What is an LLM?

Data
+
Neural Network
→
LLM

A Large Language Model is a deep-learning model trained on billions of text samples to predict the next token. It learns patterns, grammar, facts, and reasoning from text.

ConceptMeaning
TokenA piece of a word (~4 chars)
Context WindowHow much text the LLM can "see"
PromptInput sent to the model
Temperature0 = precise, 1 = creative
InferenceCalling the model to get output
# LLM call (main.py)
from langchain_google_genai import ChatGoogleGenerativeAI
from dotenv import load_dotenv

load_dotenv()  # reads GOOGLE_API_KEY from .env

# 1. Create model instance
model = ChatGoogleGenerativeAI(
    model="gemini-3.1-flash-lite"
)

# 2. Send a prompt → get a response
response = model.invoke("What is the capital of India?")

# 3. Read the text
print(response.text)  # → "New Delhi"
💡 Remember: the model doesn't actually "know" things. It predicts the next word based on patterns from training data.

Fundamentals

Messages & Roles

Every LLM conversation uses three roles. Understanding these is essential for everything that follows.

⚙️

SystemMessage

Sets the AI's personality, rules, and behaviour. Written by the developer. Processed first.

🧑

HumanMessage

The user's question or input. What the person types.

🤖

AIMessage

The model's reply. Stored in history so the model remembers what it said.

from langchain_core.messages import (
    SystemMessage,
    HumanMessage,
    AIMessage
)

# A conversation is just a list of messages
conversation = [
    # Role: System (developer sets this)
    SystemMessage(content="You are a Python expert."),

    # Role: Human (user's input)
    HumanMessage(content="What is a list comprehension?"),

    # Role: AI (model's previous reply)
    AIMessage(content="A list comprehension is..."),

    # Role: Human (follow-up question)
    HumanMessage(content="Give me an example.")
]

# Send the whole list — model sees full context
response = model.invoke(conversation)

GenAI vs Agentic AI

GenAI vs Agentic AI

🗣️ Generative AI

A single, stateless request → response cycle. The model answers but cannot act.

User Prompt
→
LLM
→
Text Response
  • ❌ No memory between sessions
  • ❌ Cannot take real-world actions
  • ❌ Cannot call APIs or run code
  • ✅ Fast, simple, low cost
Example: "Write me a poem about Bangalore"

🤖 Agentic AI

The LLM reasons, plans, and executes multi-step tasks using tools. It loops until done.

1. User: "Email me a weather report for Bangalore"
↓ Think: "I need to 1) get weather, 2) write email, 3) send"
2. Call Tool: get_weather("Bangalore") → 28°C Cloudy
3. Call Tool: write_email(weather_data) → HTML email
4. Call Tool: send_email(to, html) → Sent!
5. Reply: "Done! Email sent with weather report."
🔑 Key point: The LLM doesn't execute tools, it only requests them. The actual function runs in our code and the result gets fed back.

GenAI vs Agentic AI

The Agent Loop: ReAct Pattern

The most common agent pattern is ReAct (Reason + Act). The agent thinks, acts, observes the result, and repeats.

1
REASON: What do I need to do?
↓
2
ACT: Call a tool (or give final answer)
↓
3
OBSERVE: What did the tool return?
↓ loop back to REASON
✓
FINAL ANSWER: Task complete
FeatureGenAIAgentic AI
ModeRequest→ResponsePlan→Act→Loop
MemoryNoneShort + Long term
Tools❌✅ APIs, DB, Code
Decisions❌✅ Branch, retry
Multi-step❌✅
CostLowHigher (more calls)
FrameworksLangChainLangGraph
⚠️ More power = more responsibility. Agentic AI can take real actions, so always add guardrails!

Memory

Why Memory Matters

LLMs are stateless by default. Without memory, every call is independent.

❌ Without Memory

User: "My name is Navin"
AI: "Hello Navin!"
User: "What is my name?"
AI: "I don't know your name." ← Wrong!

✅ With Memory

User: "My name is Navin"
AI: "Hello Navin!"
User: "What is my name?"
AI: "Your name is Navin." ← Correct!
TypeHowBest For
In-ContextAppend all messagesShort conversations
SummarizationSummarize old messagesLong conversations
Vector DBSimilarity searchKnowledge bases
CheckpointerPersist graph stateMulti-session agents
💡 In-context memory is the simplest: just pass the entire chat_history list on every call. The list is the memory.

Memory

In-Context Memory: Code

# ChatBot.py — In-context memory (chat history)
from langchain_google_genai import ChatGoogleGenerativeAI
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage

model = ChatGoogleGenerativeAI(model="gemini-3.1-flash-lite")

# ✅ Start with system prompt — this stays throughout
chat_history = [
    SystemMessage(
        content="You are a helpful Coding AI assistant."
    )
]

while True:
    user_input = input("You: ")
    if user_input.lower() == "exit":
        break

    # ✅ Add user message to history
    chat_history.append(HumanMessage(content=user_input))

    # ✅ Send ENTIRE history — this is the memory!
    response = model.invoke(chat_history)

    # ✅ Add AI reply to history for next round
    chat_history.append(AIMessage(content=response.text))

    print(f"AI: {response.text}")

What's happening:

Turn 1: [System, Human("My name is Navin")] → AI
↓ append AIMessage to list
Turn 2: [System, Human, AI, Human("What's my name?")] → AI
↓ AI sees full history → "Your name is Navin"

step1 = PromptTemplate(
    template="Write an article on {topic}")

step2 = PromptTemplate(
    template="Create 5 MCQs based on:\n{article}")

# ✅ Chain: topic → article → MCQs
chain = (step1
       | model
       | StrOutputParser()
       | step2
       | model
       | StrOutputParser())

result = chain.invoke({'topic': 'AI in IT'})

LangChain

Structured Output: Typed Python Objects

# Structured_Output.py
from pydantic import BaseModel, Field
from typing import Literal

# ✅ Define EXACTLY what you want back
class Feedback(BaseModel):
    name: str = Field(description="Participant name")
    sentiment: Literal['positive', 'negative'] = Field(
        description="Sentiment of feedback"
    )
    highlights: list[str] = Field(
        description="List of positive points"
    )
    rating: str = Field(description="Rating out of 5")

# ✅ Bind schema to model
structured_model = model.with_structured_output(Feedback)

# ✅ Feed raw text — get typed object back
result = structured_model.invoke(
    "The Java training was great. Trainer was excellent. 
     Rating: 4/5. Name: Navin Kumar."
)

print(result.sentiment)   # → "positive"
print(result.name)        # → "Navin Kumar"
print(result.rating)      # → "4/5"

Instead of parsing text manually, we tell the LLM the exact structure we need. It returns a validated Python object.

"The Java training was great..." (raw text)
↓ structured_model.invoke()
Feedback( name="Navin Kumar", sentiment="positive", rating="4/5", highlights=[...] )
🏆 Use Structured Output when the output needs a specific format: routing decisions, data extraction, classification, form filling.

LangGraph

LangGraph: Agent State Graphs

LangGraph adds a graph-based execution model on top of LangChain. Think of it as a flowchart where each box is an AI function.

ConceptDescription
StateTypedDict (data flowing through graph)
NodePython function that reads/writes state
EdgeArrow connecting nodes
Conditional EdgeBranch based on state value
compile()Lock graph, make it runnable
invoke()Run the graph with an input
💡 LangGraph is what powers LangChain Agents internally. It's the execution engine for the agentic loop.
# Chatbot.py — Simplest LangGraph
from langgraph.graph import START, END, StateGraph
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages

# 1. Define STATE
class ChatBotState(TypedDict):
    # add_messages = APPEND, not replace
    messages: Annotated[list, add_messages]

# 2. Define a NODE
def ChatBotNode(state: ChatBotState):
    result = llm.invoke(state['messages'])
    return {'messages': [result]}

# 3. Build GRAPH
graph = StateGraph(ChatBotState)
graph.add_node('ChatBotNode', ChatBotNode)
graph.add_edge(START, 'ChatBotNode')
graph.add_edge('ChatBotNode', END)

# 4. COMPILE and RUN
workflow = graph.compile()
response = workflow.invoke({
    'messages': HumanMessage(content="Hello!")
})

LangGraph: Conditional Routing

Real-world agents need to branch, meaning go to different nodes based on data. From main.py (Feedback Email System):

[START]
↓
[AnalyzeFeedback]
↓ conditional edge
positive
[GeneratePositiveEmail]
negative
[GenerateNegativeEmail]
↓
[SendEmailNode]
↓
[END]
# main.py — Conditional routing
from typing import Literal

# ✅ Conditional edge function
#    Returns the NAME of the next node
def CheckCondition(state) -> Literal[
        "GeneratePositiveEmail",
        "GenerateNegativeEmail"]:
    if state["sentiment"] == "positive":
        return "GeneratePositiveEmail"
    else:
        return "GenerateNegativeEmail"

# ✅ Wire up conditional routing
graph.add_conditional_edges(
    "AnalyzeFeedback",
    CheckCondition
)

# ✅ Structured Output for classification
class FeedBack(BaseModel):
    sentiment: Literal["positive", "negative"]
    participant_name: str
    rating: str
    email_address: str

def AnalyzeFeedback(state) -> AgentState:
    structured_model = llm.with_structured_output(FeedBack)
    response = structured_model.invoke(state["feedback"])
    return {
        "sentiment": response.sentiment,
        "participant_name": response.participant_name,
    }

Tools

Tool / Function Calls

A tool is a Python function the LLM can request to be called. The LLM decides which tool to call and with what arguments.

"Add 'Buy milk' to my todo list"
↓ LLM decides: call add_todo
LLM outputs: {tool: "add_todo", args: {todo: "Buy milk"}}
↓ LangChain executes the function
add_todo("Buy milk") → "Todo added"
↓ Result fed back to LLM
"Done! 'Buy milk' added to your todos."
⚠️ The docstring is CRITICAL. It tells the LLM what the tool does and when to use it. Write clear, specific docstrings!
# Task_Manager.py — Tool definitions
from langchain.tools import tool

# ✅ @tool decorator = LLM-callable function
# ✅ Docstring = instructions for the LLM
# ✅ Type hints = tells LLM expected arg types

@tool
def add_todo(todo: str):
    """Add a new todo item to the database."""
    cursor.execute(
        "INSERT INTO todos VALUES (?,?)", (todo, False))
    con.commit()
    return "Todo added successfully"

@tool
def get_all_todos():
    """Get all todo items from the database."""
    cursor.execute("SELECT * FROM todos")
    return cursor.fetchall()

@tool
def delete_todo(todo_id: int):
    """Delete a todo by its ID."""
    cursor.execute("DELETE FROM todos WHERE id=?", (todo_id,))
    con.commit()
    return f"Todo {todo_id} deleted"

Tool Agent: Register & Use Tools

# Create an agent with tools
from langchain_google_genai import ChatGoogleGenerativeAI
from langchain.agents import create_agent
from langgraph.checkpoint.memory import InMemorySaver

llm = ChatGoogleGenerativeAI(model="gemini-3.1-flash-lite")

# ✅ Register all tools with the agent
agent = create_agent(
    model=llm,
    system_prompt="You are a task manager. Use tools.",
    tools=[add_todo, get_all_todos, delete_todo, update_todo],
    checkpointer=InMemorySaver()  # memory!
)

# ✅ thread_id = separate conversation per user
config = {"configurable": {"thread_id": 1}}

while True:
    user_input = input("You: ")
    if user_input.lower() == "exit": break
    response = agent.invoke(
        {"messages": [{"role": "user", "content": user_input}]},
        config=config
    )
    print(response["messages"][-1].text)

ToolNode in LangGraph

from langgraph.prebuilt import ToolNode, tools_condition

tools = [add_todo, get_all_todos, delete_todo]
llm_with_tools = llm.bind_tools(tools)

    return {"messages": [llm_with_tools.invoke(state["messages"])]}

graph.add_node("agent", agent_node)
graph.add_node("tools", ToolNode(tools))
graph.add_conditional_edges("agent", tools_condition)
graph.add_edge("tools", "agent")  # ← loop back!

Human-in-the-Loop

Human-in-the-Loop (HITL)

Agents can make irreversible mistakes. HITL adds a pause-point where a human reviews before the agent proceeds.

📧

Approve/Reject

Pause before sending emails, notifications, or posts

💰

Financial Actions

Approve before any money transfer or budget spend

🗑️

Delete Operations

Confirm before deleting records or files

✏️

Review & Edit

Human can edit AI content before it's used

# main.py — interrupt() pauses the graph
from langgraph.types import interrupt, Command

@tool
def Send_Email(email_address: str, body: str):
    """Send an email. Requires human approval."""

    # ✅ PAUSE — saves graph state, waits for human
    decision = interrupt("Do you want to send this email?")

    if decision.lower() == "yes":
        # send the email
        return "Email sent!"
    else:
        return "Email cancelled."

# Checkpointer REQUIRED for interrupt
app = graph.compile(checkpointer=InMemorySaver())

# 1st run — hits interrupt(), pauses
app.invoke({"feedback": user_input}, config=config)

# Human decides
human_answer = input("Approve? (yes/no): ")

# Resume — graph continues from where it paused
app.invoke(Command(resume=human_answer), config=config)
💡 The graph state is saved to the checkpointer when interrupt() fires. The same thread_id resumes from exactly where it stopped.

Bonus: RAG

RAG (Retrieval-Augmented Generation)

Problem: The LLM has no knowledge of our internal documents. RAG solves this without fine-tuning.

1. Load documents (PDF, Word, web)
↓
2. Chunk into small pieces (500 chars)
↓
3. Embed → convert text to vectors
↓
4. Store in ChromaDB (vector database)
↓
At query time:
5. User question → find similar chunks
↓
6. Inject chunks into prompt as context
↓
7. LLM answers using YOUR data
# Langchain-RAG/main.py
# ── 1. Load ──
loader = PyPDFLoader("./Documents/HR-Policy.pdf")
docs = loader.load()

# ── 2. Chunk ──
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500, chunk_overlap=100)
chunks = splitter.split_documents(docs)

# ── 3+4. Embed & Store ──
embeddings = GoogleGenerativeAIEmbeddings(
    model="gemini-embedding-001")
vectordb = Chroma.from_documents(
    chunks, embeddings, persist_directory="./ChromaDB")

# ── 5. Retrieve ──
retriever = vectordb.as_retriever(search_kwargs={"k": 5})

# ── 6. Prompt with context ──
prompt = PromptTemplate(template="""
You are an HR assistant.
Answer using ONLY the context below.
Context: {context}
Question: {question}""")

# ── 7. Build RAG chain ──
rag_chain = (
    RunnableParallel(
        context=retriever,
        question=RunnablePassthrough()
    ) | prompt | llm | StrOutputParser()
)

answer = rag_chain.invoke("What is the leave policy?")

Dos and Don'ts When Building Agents

❌ Avoid This

✗
Only adding HumanMessage to history
The AI's reply is part of the conversation too. Forget it and the bot loses context of what it said.
✗
Skipping the @tool docstring
The LLM decides which tool to call based only on the docstring. No docstring = LLM picks randomly.
✗
Letting agents run destructive actions freely
Sending emails or deleting records can't be undone. Without a pause, one hallucination causes real damage.
✗
Reusing the same thread_id for everyone
All users end up sharing the same memory. Their conversations leak into each other.

✅ Do This Instead

✓
Append both messages every turn
Add HumanMessage before calling the model, then AIMessage after. That list is the memory.
✓
Write a clear @tool docstring
Describe what the tool does and when to call it. If you understand it in plain English, the LLM will too.
✓
Use interrupt() before any risky action
One line to pause the agent, show the human what's about to happen, and wait for a yes or no.
✓
Use a unique thread_id per user
One ID per person keeps their session memory isolated. Think of it as a separate conversation folder.
💡 Start simple: one agent + two tools. Get it working first, then add complexity only when you need it.

Start with LangChain when:

  • Building a RAG chatbot
  • Need structured output
  • Simple prompt pipelines

  • Complex branching logic
  • Need human approval
